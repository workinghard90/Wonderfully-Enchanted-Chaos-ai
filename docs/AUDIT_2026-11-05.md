## Audit findings

1. **Controlled rejection gap (fixed by audit PR #83):** The new artwork
   archive validated images with Pillow but did not catch
   `Image.DecompressionBombError`. An archived, checksummed image with
   excessive declared dimensions could raise an unhandled exception instead
   of receiving the expected 409 response and recoverable failed receipt.
   This PR catches that explicit Pillow exception and tests a low mocked
   pixel threshold without allocating giant images.
2. **CI turnaround:** The workflow runs six Python combinations plus
   independent media, browser and container jobs. The browser job installs
   Chromium, FFmpeg and PDF utilities; media separately installs FFmpeg;
   container builds the full Docker image. The full suite is valuable, but
   repeated dependency installation and every-PR full-media validation
   contribute to long turnaround. Recommended follow-up: measure per-step
   duration, introduce dependency/image caching safely, and retain the
   full suite as the required release gate. Do not reduce test coverage
   simply to make PRs faster.
3. **Private live acceptance pending:** A green CI run does not establish
   private owner login behavior, actual persistent disk headroom, or a
   successful real browser save/download on the currently deployed SHA.
   Before deployment: do a separate non-destructive, owner-authenticated
   readiness check, a test-only project snapshot restore, and verify one
   real ZIP using a local SHA-256 comparison. Never overwrite original
   owner projects to perform acceptance.
4. **Artwork ZIP scope:** It is verified original PNG/JPEG artwork with
   SHA-256 manifest and a reversible *permission* (revocation blocks future
   download). It is not a PDF, commercial-use clearance, print quality
   certification, or auto-publish authorization. Already downloaded files
   cannot be recalled by revocation.
5. **Resource bounds:** Export size is bounded to 36 MiB with a 64 MiB disk
   headroom check; this is not an automatic quota for aggregate persistent
   exports. A follow-up should assess multi-export retention, disk capacity
   impact, and an owner-controlled, audited cleanup process, without
   silently deleting original or exported files.
